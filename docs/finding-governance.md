# Finding Governance

## Hybrid model
Centralize schema, severity vocabulary, deduplication, lifecycle controls, and audit requirements while retaining project-aware triage and remediation workflows.

## Lifecycle
DRAFT → TRIAGED → VALIDATING → CONFIRMED / REJECTED / NEEDS_MORE_EVIDENCE → ACCEPTED → REMEDIATION_TRACKED → VERIFIED_FIXED / RISK_ACCEPTED / CLOSED.

Transitions require role authorization and supporting evidence. Reopen when new evidence undermines closure.

## Claim requirements
Title, affected in-scope asset, scope reference, weakness class, preconditions, impact, reproducible evidence, confidence, severity rationale, root cause, remediation, references, and validation history.

Do not report inference as confirmed vulnerability. Do not merge distinct root causes because symptoms look alike. A ticket closure or claimed fix is not proof of remediation.
